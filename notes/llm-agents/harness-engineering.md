## 핵심
**하네스 엔지니어링**은 모델을 더 똑똑하게 만드는 게 아니라, 모델이 일할 *환경*을 설계하는 일이다. 미첼 하시모토의 정의로 "에이전트가 실수할 때마다 그 실수가 다시는 반복되지 않도록 하는 것"이고, 더 구체적으로는 **모델 가중치 외부의 모든 것**이다.

## 상세
- **구성 요소**: 지침 파일(`AGENTS.md`/`CLAUDE.md`), 도구(MCP·스킬), 도메인 지식을 인코딩한 LLM 위키, 검증 도구(린트·타입체커·자동화 테스트). → 이 위키 자체도 하네스의 한 부품이다.
- **왜 필요한가**: 최신 모델일수록 똑똑하지만 자기 코드에 관대해 "이 정도면 됐다"며 끝내고, 코드만 봐선 알 수 없는 도메인 맥락(인증 절차·테스트 계정·환경 분기)을 모른다. 그래서 공식 에이전트를 설치만 해서는 헤맨다 — "신입 온보딩"처럼 맥락을 직접 줘야 한다.
- **검증 수단의 중요성**: 보리스 체르니(Claude Code) — "에이전트에게 자기 작업을 검증할 수단을 줘라. 늘 결과를 2~3배 끌어낸다." 검증 수단을 주면 에이전트가 [[self-improvement-loop]]를 돌 수 있다.
- **진화한다**: 하네스는 "지금 모델이 못하는 걸 사람이 보강하는 자리"다. 모델이 좋아지면 일부는 자동화되지만 더 어려운 일을 맡기게 되어 새 자리에 사람 손이 필요해진다 → 사라지지 않고 모양을 바꾸며 함께 자란다.
- **사람의 역할**: ①자가개선 루프 설계 ②도구·맥락 제공 ③모델 진화에 맞춰 하네스 진화. 카파시 — "사고(thinking)는 위임해도 책임(taste)은 위임 못 한다." Vercel 원칙 — "올바른 행동을 쉽게 할 수 있도록 환경을 만들어라."
